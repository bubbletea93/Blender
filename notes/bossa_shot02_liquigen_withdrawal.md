## Native LiquiGen setup

Open the prepared `withdrawal_test.liquigen` for the configured 6,000-viscosity candidate. Its imports use absolute paths in this checkout. Check that all three imports load at the correct scale before playing or exporting. The steps below describe its wiring and can also be used to rebuild the test through the native UI.

1. Create a separate project in the installed LiquiGen. Import the three FBX files using separate **Import** nodes, each with **Scale = 1%** and relative geometry resolution **200%**. Leave the project master scale at **1×**. Set the applicator import to animated, **25 fps**, zero time offset, and no animation loop. Keep the other imports static. Check the compensated dimensions against the manifest and inspect the native import log for discarded triangles before accepting a run.
2. Connect the applicator and container **Geometry** outputs to **Collider** nodes, then connect their **Collider** outputs to the **Simulation / Colliders** input. Leave **Invert Shape** off: the exported container already has a hollow interior and solid walls.
3. Connect the initial-lacquer import's **Geometry** output to an **Emitter / Shapes** input. Select **Volume**, **Fill**, and **Just once**; leave **Reset previous liquid** off and initial speed zero. Connect **Emitter** to **Simulation / Emitters**. The settling interval lets the liquid establish contact around the immersed shaft and brush.
4. Connect **Simulation / Liquid** to **Meshing / Liquid**, then **Meshing / Mesh** to both **Scene / Mesh** and **Export: Mesh / Mesh**. Use downward gravity and disable automatic simulation reset. Do not add whitewater or foam for this test.
5. Keep the project and any variants in `references/brush_liquid_motion/liquigen_test/`, separate from the production scenes.

The [official import guide](https://docs.jangafx.com/liquigen/pages/references/How-To%20Guides/import_animation.html) requires closed simulation geometry; features thinner than the voxel size cannot be represented reliably. The test uses a solid brush envelope rather than attempting fluid flow between individual bristles.

## Export and assessment

For each candidate, export an **Alembic mesh**, Blender convention, first frame **0**, **301 samples**, stride **1**, numbering offset **0**, and **FPS compensation enabled**. At 100 Hz this covers 0-3 seconds, matching the test's frame-0 to frame-75 interval. Give each viscosity run a separate directory under `cache/gel_polish_bossa_shot02_withdrawal_test/`.

Import into a separate Blender test scene at 25 fps and verify time zero, the lift start, and the frame-55 hold against the collider animation. Inspect the full sequence for wall leaks, disappearing liquid, detached floating film, excessive stringiness, and intersections. Use the approved opaque lacquer shader; transparent liquid shading would disguise the intended consistency. Leave cache velocity motion blur disabled until its scaling and timing are checked.

The final approach should retain an **authored thin wet film on the shaft/ferrule** and use the simulation for the thicker moving liquid, meniscus, and separating strand. A finite-resolution solver will not automatically reproduce the thin surface film, individual bristle flexibility, or the exact rheology of this polish. Matching this axial test is the first step; the production withdrawal would need its own collider motion, continuous timing across the Shot 01/02 cut, and a validated cache before integration.
